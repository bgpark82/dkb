# 코루틴 (Coroutines)

코루틴은 비동기적으로 실행되는 코드를 단순화하기 위해 Android에서 사용할 수 있는 동시성 디자인 패턴입니다. 코루틴은 Kotlin 1.3 버전에 추가되었으며 다른 언어에서 확립된 개념을 기반으로 합니다.

Android에서 코루틴은 기본 스레드를 차단하여 앱이 응답하지 않게 만들 수 있는 장기 실행 작업을 관리하는 데 도움이 됩니다. 코루틴을 사용하는 전문 개발자의 50% 이상이 코루틴을 통해 더 깨끗하고 간결한 코드를 작성하는 데 도움이 되었다고 보고했습니다.

## 특징

코루틴은 Android의 비동기 프로그래밍을 위한 권장 솔루션입니다. 주목할 만한 기능은 다음과 같습니다.

*   **경량 (Lightweight)**: 코루틴이 실행 중인 스레드를 차단하지 않는 *일시 중단(suspension)*을 지원하므로 단일 스레드에서 많은 코루틴을 실행할 수 있습니다. 일시 중단은 많은 동시 작업을 지원하면서 차단(blocking)에 비해 메모리를 절약합니다.
*   **메모리 누수 감소**: 범위 내에서 작업을 실행하려면 *구조화된 동시성(structured concurrency)*을 사용합니다.
*   **기본 제공 취소 지원**: 취소는 실행 중인 코루틴 계층을 통해 자동으로 전파됩니다.
*   **Jetpack 통합**: 많은 Jetpack 라이브러리에는 전체 코루틴 지원을 제공하는 확장 기능이 포함되어 있습니다. 일부 라이브러리는 구조화된 동시성에 사용할 수 있는 자체 코루틴 범위를 제공하기도 합니다.

`launch`와 `async`는 둘 다 새로운 코루틴을 시작하는 코루틴 빌더이지만, 주요 차이점은 **결과 반환 여부와 예외 처리 방식**입니다.

-----

### `launch`

* **결과 반환**: `launch`는 **결과를 반환하지 않습니다.** "fire-and-forget" 스타일의 작업에 사용됩니다. 즉, 작업을 시작하고 그 결과를 기다리거나 사용하지 않을 때 적합합니다.
* **반환 타입**: `Job` 객체를 반환합니다. 이 `Job`을 사용해 코루틴을 취소하거나 완료될 때까지 기다릴 수 있지만, 결과 값을 얻을 수는 없습니다.
* **예외 처리**: `launch` 내부에서 예외가 발생하면 즉시 전파되어 코루틴 스코프의 부모를 통해 처리됩니다. 이는 일반적으로 애플리케이션의 크래시로 이어질 수 있습니다.

**예시**: 사용자 인터페이스(UI)를 업데이트하거나, 서버에 데이터를 보내는 등 결과가 필요 없는 작업을 수행할 때 사용합니다.

```kotlin
// UI 업데이트나 로그 전송처럼 결과를 기다릴 필요 없는 작업
launch {
    // 작업 수행
    println("백그라운드에서 로그 전송 중...")
}
```

-----

### `async`

* **결과 반환**: `async`는 **결과를 반환합니다.** 계산의 결과값이 필요할 때 사용됩니다.
* **반환 타입**: `Deferred<T>` 객체를 반환합니다. `Deferred`는 미래에 결과값을 얻을 수 있도록 약속하는 객체로, `.await()`를 호출하여 실제 결과(`T`)를 얻을 수 있습니다.
* **예외 처리**: `async` 내부에서 발생한 예외는 **`.await()`가 호출될 때까지 지연됩니다.** 즉, `.await()`를 호출하지 않으면 예외가 발생해도 감지되지 않을 수 있습니다.

**예시**: 두 개의 API를 동시에 호출하고 그 결과를 합쳐야 하는 경우에 사용합니다.

```kotlin
// 두 API 호출을 동시에 시작하고 결과를 결합
val user = async { fetchUserData() }
val profile = async { fetchProfileData() }

// 두 작업이 모두 완료될 때까지 기다리고 결과를 사용
val userData = user.await()
val profileData = profile.await()
```

-----

### 주요 차이점 요약

| 특징 | `launch` | `async` |
| :--- | :--- | :--- |
| **목적** | 결과를 반환하지 않는 작업 (fire-and-forget) | 결과를 반환하는 작업 (계산) |
| **반환 값** | `Job` | `Deferred<T>` |
| **예외 전파** | 즉시 전파 | `.await()` 호출 시 지연 전파 |


## 코루틴 vs. 스레드 (Coroutines vs. Threads)

코루틴을 "경량 스레드(lightweight thread)"라고 부르는 이유는 스레드와 유사한 목표(동시 작업 처리)를 가지면서도 훨씬 적은 비용으로 동작하기 때문입니다.

| 특징 | 스레드 (Thread) | 코루틴 (Coroutine) |
| :--- | :--- | :--- |
| **관리 주체** | 운영체제 (OS) | Kotlin 런타임 |
| **무게** | **무거움 (Heavyweight)**: OS가 스레드를 만들고 컨텍스트를 전환(context switching)하는 데 많은 비용(메모리, CPU 시간)이 듭니다. | **가벼움 (Lightweight)**: 하나의 스레드 위에서 수천, 수만 개의 코루틴을 만들 수 있습니다. 코루틴 간의 전환은 OS 개입 없이 런타임 레벨에서 일어나므로 비용이 매우 적습니다. |
| **동작 방식** | **블로킹 (Blocking)**: 스레드가 I/O 작업(예: 네트워크 요청, 파일 읽기)을 기다릴 때, 해당 스레드는 작업이 끝날 때까지 **멈춥니다(block)**. 그동안 스레드는 다른 일을 할 수 없습니다. | **일시 중단 (Suspending)**: 코루틴은 I/O 작업을 기다릴 때 **일시 중단(suspend)**됩니다. 이때 코루틴을 실행하던 스레드는 다른 코루틴을 실행하는 등 다른 작업을 할 수 있습니다. I/O 작업이 완료되면 코루틴은 가용한 스레드에서 실행을 재개합니다. 이것이 **논블로킹(non-blocking)** 방식입니다. |

**핵심 차이**: 스레드는 **블로킹**하고, 코루틴은 **일시 중단**합니다. 이 차이 덕분에 코루틴은 적은 수의 스레드로도 수많은 동시 작업을 효율적으로 처리할 수 있습니다.

## 동시성(Concurrency)과 병렬성(Parallelism)

*   **동시성 (Concurrency)**: 여러 작업을 **동시에 다루는 것**입니다. 작업들이 꼭 같은 순간에 실행될 필요는 없습니다. 하나의 CPU 코어에서도 여러 작업을 번갈아 가며 실행하여 동시성을 달성할 수 있습니다. (예: 한 명의 바리스타가 여러 손님의 주문을 번갈아 처리하는 것)
*   **병렬성 (Parallelism)**: 여러 작업을 **물리적으로 동시에 실행하는 것**입니다. 이를 위해서는 여러 개의 CPU 코어가 필요합니다. (예: 여러 명의 바리스타가 각자 다른 손님의 주문을 동시에 처리하는 것)

### 코루틴이 동시성과 병렬성에 효과적인 이유

1.  **동시성 처리**: 코루틴은 **논블로킹 일시 중단** 특성 덕분에 동시성 처리에 매우 뛰어납니다. I/O 작업이 많은 애플리케이션(예: 네트워크 통신, 데이터베이스 접근)에서 코루틴을 사용하면, 작업 대기 시간에 스레드가 멈추지 않고 다른 일을 계속할 수 있으므로 시스템 자원을 극도로 효율적으로 사용합니다. 이것이 코루틴의 가장 큰 강점입니다.

2.  **병렬성 처리**: 코루틴은 `Dispatcher`를 통해 작업을 여러 스레드에 분배하여 병렬성을 달성할 수 있습니다. 예를 들어, `Dispatchers.Default`는 CPU 집약적인 작업을 위해 백그라운드 스레드 풀(thread pool)을 사용합니다. 여러 계산 작업을 `async` 빌더로 동시에 시작하고 나중에 `await`로 결과를 합치면, 멀티코어 CPU에서 이 작업들이 병렬로 실행되어 전체 처리 시간을 단축할 수 있습니다.
